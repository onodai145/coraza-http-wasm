# 既知のバグと更新判定

状態: ユーザーの指示により、以下の2件は今回の更新では未修正の既知バグとして管理する。
標準Traefikを維持し、Traefik本体のカスタムビルドは採用しない。
この分類は修正済み・全テスト成功・公開承認・本番適用承認を意味しない。

## 対象構成

Coraza v3.8.1 / CRS v4.30.0 / HTTP WASM host v0.7.0 / Traefik v3.6.0。
Go 1.26.10 / TinyGo 0.43.0。ツールチェーンはmiseで固定する。
依存、ホスト、ツールチェーン、検査設定を変更したときは、以下の再現条件と影響範囲を再評価する。

## 1. SSEの逐次配信が機能しない

- 区分: HTTP配信互換性。CRSのルール検知とは別の評価項目。
- 対象: CorazaのHTTP E2E内の`Legitimate SSE response stream`。
- 再現: `mise exec -- go run mage.go e2e`。
- 確認済み症状: 従来HTTP9ケースが成功した後、SSEはHTTP200となるが`no event received; not streamed`で失敗する。
- 原因範囲: HTTP WASM連携の応答バッファリングとhostのFlusher未対応。
- 運用: この構成をSSEルートへ適用しない。現在SSE利用サービスはない可能性が高いとユーザーから回答あり。利用開始時に対応方針を再評価する。
- 状態: 未修正。SSEの検査対象から外すだけで逐次配信が直ることは確認していない。

## 2. raw fragmentの拒否がCRSテストの期待に達しない

- 区分: CRSのHTTPプロトコル検査との互換性。
- 対象: FTW `920610-2`。`/#fragment`にHTTP400を期待する。
- 再現: `mise exec -- go run mage.go ftw`。
- 確認済み症状: ホストがパスをEscapedPath()で再構成し、生の`#`が`%23`となってguestへ渡る。期待する400拒否にならない。
- 影響: この不正リクエストが拒否される保証はない。正当なエンコード済み`%23`との一律遮断は行わない。この1件からCRS全体の無効化や、具体的なアプリケーションへの悪用成立は断定しない。
- 状態: 標準ホストでは未修正。通常Corazaコネクタでも同じ期待値不一致を確認した。
- 参考: [ホスト修正案](host-request-target.md)。隔離した修正ホストではFTW全件対象が成功したが、標準Traefikには未適用。

## 更新の完了判定

| 条件 | 判定 |
|---|---|
| ビルド・unit・実CRS・本文保持・遮断応答・通常HTTP・Traefik統合が成功 | 必須 |
| 全E2Eと全FTWを最後まで実行し、上記2件だけが同じ理由で失敗 | 「既知バグあり」としてレビュー・コミットを進められる |
| 基本機能・互換性検証での新たな失敗、同じケースでも別原因の失敗、実行中断、結果欠落 | 更新確定とリリースを停止する |
| 上記の既知バグが成功へ変化 | 原因を確認し、既知バグ一覧と影響範囲を見直す |
| 公開・本番適用 | 負荷試験と最終レビューを実施し、別途ユーザー承認を得る |

例外はSSEの当該ケースとFTW 920610-2だけに限定する。
`TestE2E`全体の失敗を一括して許容してはいけない。従来9ケースや実CRS・本文保持などがすべて成功していることを確認する。
OOM、タイムアウト、host trap、初期化失敗、一般のネットワークエラーは既知バグに含めない。
現在のFTW基準はCRS v4.30.0で5,193件、skip 0、既存ignore 107件。
依存更新で対象件数が変わる場合は差分を確認し、件数の減少を見逃さない。
成功扱いにする目的でテストの削除・skip・ignore追加・期待値の緩和を行わない。

## CIと成果物

- `mage e2e` / `mage ftw`の生の終了コードと失敗ログを保持する。
- 結果の表記は「全テスト成功」「既知バグあり」「新たな失敗／未検証」を区別する。
- CIの自動分類が未実装の間は、全ログと失敗ケースを手動確認して分類する。終了コードだけで既知バグと判定しない。
- 現在のCIは既知失敗の非0終了を保持し、既知の2件がある間も失敗となり、自動のDraft Release生成を止める。既知バグの分類だけを理由に`continue-on-error`等で一括通過させない。
- 調査用WASM artifactの保存と、配布候補としての承認を区別する。
- 配布候補にはコミット、依存・ツールチェーン、WASMのSHA256、検証ログ、既知バグ一覧を紐付ける。
- 公開する場合は既知バグをRelease説明へ記載し、ユーザー承認を得て手動で公開する。自動の本番反映は行わない。

今回の既知バグ受容により、2件が未修正であることだけを理由に更新差分のレビュー・コミットを停止し続けない。
負荷試験、最終レビュー、公開・本番適用の承認は独立した残作業として扱う。

## 2026-11-09の範囲整理

ユーザー指定により、今回の目標はCRS更新と実ルールでの基本動作確認までとする。サービス別の入力上限の決定・任意ルールの採用、本番性能の調整は別作業。これらを今回のレビュー・コミットの前提にしない。
負荷試験の502・資源閾値停止・長大引数の遅延は[記録](load-validation.md)に残し、既知2件へ含めたり成功扱いにしたりしない。本番適用の判断は別途必要。通常CIの失敗判定、公開・本番適用の承認条件は維持する。
